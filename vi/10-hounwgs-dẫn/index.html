hướng dẫn

Tổng Quan Kiến Trúc

Dựa trên hướng dẫn chi tiết đã thiết kế, đây là số lượng từng dịch vụ AWS sẽ sử dụng:

1. Amazon RDS Aurora

Primary Region (ap-southeast-1):

• 1 Aurora MySQL Cluster (Primary) • 1 Writer Instance (Serverless v2: 0.5-16 ACU) • 1 Reader Instance (Serverless v2: 0.5-8 ACU)

Secondary Region (us-west-2):

• 1 Aurora MySQL Cluster (Secondary) • 2 Reader Instances (Serverless v2: 0.5-4 ACU mỗi instance)

Global Database:

• 1 Aurora Global Database (kết nối 2 regions)

Tổng Aurora: 2 clusters, 4 instances, 1 global database

2. Amazon VPC

Primary Region:

• 1 VPC (10.0.0.0/16) • 3 Private Subnets (cho Aurora) • 10.0.11.0/24 (AZ-a) • 10.0.12.0/24 (AZ-b) • 10.0.13.0/24 (AZ-c) • 1 Internet Gateway • 1 Route Table (Private)

Secondary Region:

• 1 VPC (10.1.0.0/16) • 3 Private Subnets (cho Aurora) • 10.1.11.0/24 (AZ-a) • 10.1.12.0/24 (AZ-b) • 10.1.13.0/24 (AZ-c) • 1 Internet Gateway • 1 Route Table (Private)

Tổng VPC: 2 VPCs, 6 subnets, 2 IGWs, 2 route tables

3. Amazon EC2

Testing/Management:

• 1 EC2 Instance (t2.micro) - Primary region • 1 EC2 Instance (t2.micro) - Secondary region (optional)

Tổng EC2: 1-2 instances

4. Security Groups

• 1 Security Group - Primary Aurora cluster • 1 Security Group - Secondary Aurora cluster
• 1 Security Group - EC2 instances (nếu cần)

Tổng Security Groups: 2-3 groups

5. RDS Subnet Groups

• 1 DB Subnet Group - Primary region • 1 DB Subnet Group - Secondary region

Tổng DB Subnet Groups: 2 groups

6. Amazon CloudWatch

Monitoring:

• 1 Custom Dashboard (Aurora Global Monitoring) • 5-8 CloudWatch Alarms: • High Replication Lag • High ACU Usage (Primary Writer) • High ACU Usage (Primary Reader) • High ACU Usage (Secondary Readers) • High Connection Count • CPU Utilization alerts

Metrics:

• Performance Insights (enabled cho tất cả instances) • Enhanced Monitoring (60-second intervals)

Tổng CloudWatch: 1 dashboard, 5-8 alarms

7. Amazon SNS (Optional)

• 1 SNS Topic - Alert notifications • 1-2 SNS Subscriptions (email/SMS)

Tổng SNS: 1 topic, 1-2 subscriptions

8. AWS Systems Manager (Optional)

• Parameter Store - Lưu connection strings • Secrets Manager - Lưu database credentials (recommended)

9. AWS Backup (Optional Enhancement)

• 1 Backup Plan - Cross-region backup strategy • 2 Backup Vaults (mỗi region 1)

10. Data Transfer

• Cross-Region Replication - Giữa ap-southeast-1 và us-west-2 • VPC Endpoints (optional) - Để giảm data transfer costs

Lưu Ý Tối Ưu Chi Phí

  1. Sử dụng Serverless v2 thay vì Provisioned instances
  2. Minimum ACU = 0.5 để giảm chi phí khi idle
  3. Không sử dụng NAT Gateway (chỉ private subnets)
  4. EC2 t2.micro (free tier eligible)
  5. 7-day backup retention (free tier)
  6. Performance Insights 1-day retention (free tier)

Kiến trúc này đảm bảo high availability, disaster recovery với RTO < 1 giây, và tối ưu chi phí cho môi trư ờng workshop/testing.

Phần 1: Chuẩn Bị Môi Trường

1.1 Tạo VPC và Networking (Primary Region - ap-southeast-1)

Bước 1: Tạo VPC Primary

  1. Đăng nhập AWS Console → Chọn region ap-southeast-1 (Singapore)
  2. Vào VPC service
  3. Click Create VPC • Name: aurora-primary-vpc • IPv4 CIDR: 10.0.0.0/16 • Tenancy: Default • Tags: • Environment: workshop • CostCenter: aurora-global
  4. Click Create VPC

Bước 2: Tạo Subnets cho Primary Region

Tạo 3 Private Subnets (cho Aurora):

  1. Subnet 1: • Name: aurora-primary-private-1 • VPC: aurora-primary-vpc • AZ: ap-southeast-1a • CIDR: 10.0.11.0/24

  2. Subnet 2: • Name: aurora-primary-private-2 • VPC: aurora-primary-vpc • AZ: ap-southeast-1b • CIDR: 10.0.12.0/24

  3. Subnet 3: • Name: aurora-primary-private-3 • VPC: aurora-primary-vpc • AZ: ap-southeast-1c • CIDR: 10.0.13.0/24

Bước 3: Tạo Internet Gateway

  1. Vào Internet Gateways → Create Internet Gateway
  2. Name: aurora-primary-igw
  3. Attach vào aurora-primary-vpc

1.2 Tạo VPC cho Secondary Region (us-west-2)

Chuyển sang region us-west-2 và lặp lại:

VPC Secondary: • Name: aurora-secondary-vpc • CIDR: 10.1.0.0/16

Subnets:

  1. aurora-secondary-private-1 - AZ: us-west-2a - CIDR: 10.1.11.0/24
  2. aurora-secondary-private-2 - AZ: us-west-2b - CIDR: 10.1.12.0/24
  3. aurora-secondary-private-3 - AZ: us-west-2c - CIDR: 10.1.13.0/24

Phần 2: Tạo Security Groups

2.1 Security Group cho Aurora (Primary Region)

  1. Vào EC2 → Security Groups → Create Security Group

  2. Basic Details: • Name: aurora-primary-sg • Description: Security group for Aurora Primary cluster • VPC: aurora-primary-vpc

  3. Inbound Rules: • Type: MySQL/Aurora (3306) • Source: 10.0.0.0/16 (VPC CIDR) • Description: Allow MySQL access from VPC

  4. Outbound Rules: Giữ mặc định (All traffic)

2.2 Security Group cho Aurora (Secondary Region)

Tương tự tạo ở region us-west-2: • Name: aurora-secondary-sg • VPC: aurora-secondary-vpc • Inbound: Port 3306 từ 10.1.0.0/16

Phần 3: Tạo DB Subnet Groups

3.1 Primary Region DB Subnet Group

  1. Vào RDS → Subnet groups → Create DB subnet group

  2. Details: • Name: aurora-primary-subnet-group • Description: Subnet group for Aurora primary cluster • VPC: aurora-primary-vpc

  3. Add subnets: • Chọn tất cả 3 AZ: ap-southeast-1a, 1b, 1c • Chọn các subnet private đã tạo

  4. Click Create

3.2 Secondary Region DB Subnet Group

Tương tự tạo ở us-west-2: • Name: aurora-secondary-subnet-group • VPC: aurora-secondary-vpc • Chọn 3 subnet private của secondary region

Phần 4: Tạo Aurora Primary Cluster (Tối Ưu Chi Phí)

4.1 Tạo Primary Cluster

  1. Vào RDS → Databases → Create database

  2. Engine options: • Engine type: Amazon Aurora • Edition: Aurora MySQL • Version: Aurora MySQL 8.0.mysql_aurora.3.02.0 (compatible với MySQL 8.0.28)

  3. Templates: Production (để có Global Database option)

  4. Settings: • DB cluster identifier: aurora-primary-cluster • Master username: admin • Master password: Aurora123! (hoặc tự tạo)

  5. DB instance class: • Serverless v2 (tối ưu chi phí) • Minimum ACUs: 0.5 • Maximum ACUs: 16

  6. Availability & durability: • Multi-AZ deployment: Create an Aurora Replica or Reader node in a different AZ

  7. Connectivity: • VPC: aurora-primary-vpc • DB subnet group: aurora-primary-subnet-group • Public access: No • VPC security groups: aurora-primary-sg

  8. Additional configuration: • Initial database name: testdb • Backup retention period: 7 days • Enable encryption: Yes • Performance Insights: Enable (1 day retention - free tier) • Enhanced monitoring: Enable (60 seconds)

  9. Click Create database

⏱️ Thời gian tạo: ~10-15 phút

Phần 5: Tạo Aurora Global Database

5.1 Thêm Secondary Region

  1. Sau khi Primary cluster đã Available, vào cluster details

  2. Click Actions → Add AWS Region

  3. Global database settings: • Global database identifier: aurora-global-db • Source region: ap-southeast-1 • Secondary region: us-west-2

  4. Secondary cluster configuration: • DB cluster identifier: aurora-secondary-cluster • DB instance class: Serverless v2 • Minimum ACUs: 0.5 • Maximum ACUs: 8 (thấp hơn primary để tiết kiệm)

  5. Connectivity: • VPC: aurora-secondary-vpc • DB subnet group: aurora-secondary-subnet-group • VPC security groups: aurora-secondary-sg

  6. Click Add region

⏱️ Thời gian tạo: ~15-20 phút

Phần 6: Implement Read/Write Splitting

6.1 Tạo Reader Endpoints

Primary Region:

  1. Vào Primary cluster → Connectivity & security
  2. Note lại: • Writer endpoint: aurora-primary-cluster.cluster-xxxxx.ap-southeast-1.rds.amazonaws.com • Reader endpoint: aurora-primary-cluster.cluster-ro-xxxxx.ap-southeast-1.rds.amazonaws.com

Secondary Region:

  1. Vào Secondary cluster
  2. Note lại Reader endpoint: aurora-secondary-cluster.cluster-ro-xxxxx.us-west-2.rds.amazonaws.com

6.2 Cấu hình Connection Strings

javascript // Cấu hình kết nối cho ứng dụng const dbConfig = { primary: { writer: ‘aurora-primary-cluster.cluster-xxxxx.ap-southeast-1.rds.amazonaws.com’, reader: ‘aurora-primary-cluster.cluster-ro-xxxxx.ap-southeast-1.rds.amazonaws.com’ }, secondary: { reader: ‘aurora-secondary-cluster.cluster-ro-xxxxx.us-west-2.rds.amazonaws.com’ }, credentials: { username: ‘admin’, password: ‘Aurora123!’, database: ’testdb’ } }

Phần 7: Test Disaster Recovery (RTO < 1 giây)

7.1 Chuẩn bị Test Environment

  1. Tạo EC2 Instance để test (Primary region): • AMI: Amazon Linux 2 • Instance type: t2.micro (Free tier) • VPC: aurora-primary-vpc • Subnet: Một trong các private subnet • Security group: Cho phép SSH và kết nối MySQL

  2. Cài đặt MySQL client: bash sudo yum update -y sudo yum install mysql -y

7.2 Test Failover Process

Bước 1: Kết nối và tạo test data sql – Kết nối tới writer endpoint mysql -h aurora-primary-cluster.cluster-xxxxx.ap-southeast-1.rds.amazonaws.com -u admin -p

– Tạo bảng test CREATE TABLE failover_test ( id INT AUTO_INCREMENT PRIMARY KEY, timestamp DATETIME DEFAULT CURRENT_TIMESTAMP, data VARCHAR(255) );

– Insert test data INSERT INTO failover_test (data) VALUES (‘Before failover’);

Bước 2: Thực hiện Failover

  1. Vào RDS → Databases → Aurora Global Database
  2. Click Actions → Fail over global database
  3. Chọn Secondary region (us-west-2)
  4. Planned failover: Yes (để đảm bảo không mất data)
  5. Click Fail over

⏱️ Thời gian failover: ~30-60 giây

Bước 3: Verify Failover sql – Kết nối tới endpoint mới (giờ là writer) mysql -h aurora-secondary-cluster.cluster-xxxxx.us-west-2.rds.amazonaws.com -u admin -p

– Kiểm tra data SELECT * FROM failover_test;

– Insert data mới INSERT INTO failover_test (data) VALUES (‘After failover’);

Phần 9: Cost Analysis & Optimization

9.1 Chi Phí Ước Tính (Tháng)

Aurora Serverless v2: • Primary Writer: 0.5-16 ACU × $0.12/ACU/hour × 730 hours = $43.8 - $1,401.6 • Primary Reader: 0.5-8 ACU × $0.12/ACU/hour × 730 hours = $43.8 - $700.8 • Secondary Reader: 0.5-8 ACU × $0.12/ACU/hour × 730 hours = $43.8 - $700.8

Storage: • Primary: $0.10/GB/month • Secondary: $0.10/GB/month (replicated)

Backup: • 7 days retention: Free (equal to DB size)

Data Transfer: • Cross-region replication: $0.02/GB

9.2 Tối Ưu Chi Phí

  1. Sử dụng Serverless v2 với ACU thấp: Minimum ACU: 0.5 (thay vì 1.0) Maximum ACU: Điều chỉnh theo workload thực tế

  2. Scheduled Scaling: • Giảm ACU vào giờ thấp điểm • Tăng ACU vào giờ cao điểm

  3. Monitoring và Alerting: • CloudWatch alarms cho ACU usage • Cost budgets và alerts

Phần 10: Monitoring Setup

10.1 CloudWatch Dashboards

  1. Vào CloudWatch → Dashboards → Create dashboard
  2. Name: Aurora-Global-Monitoring

Thêm các metrics quan trọng:

Database Metrics: • DatabaseConnections • CPUUtilization • ReadLatency / WriteLatency • ReadThroughput / WriteThroughput • ServerlessDatabaseCapacity (ACU usage)

Global Database Metrics: • AuroraGlobalDBReplicationLag • AuroraGlobalDBDataTransferBytes

10.2 CloudWatch Alarms

Alarm 1: High Replication Lag Metric: AuroraGlobalDBReplicationLag Threshold: > 1000ms Action: SNS notification

Alarm 2: High ACU Usage Metric: ServerlessDatabaseCapacity Threshold: > 80% of max ACU Action: SNS notification

Alarm 3: Connection Count Metric: DatabaseConnections Threshold: > 80% of max connections Action: SNS notification

10.3 Performance Insights

  1. Vào RDS → Performance Insights
  2. Chọn cluster để monitor
  3. Xem: • Top SQL statements • Wait events • Database load

Phần 11: Backup Strategies

11.1 Automated Backups

Cấu hình đã có: • Backup retention: 7 days • Backup window: Tự động • Point-in-time recovery: Enabled

11.2 Manual Snapshots

Tạo snapshot thủ công:

  1. Vào cluster → Actions → Take snapshot
  2. Name: aurora-manual-snapshot-YYYYMMDD
  3. Cross-region copy: Enable để copy sang region khác

11.3 Cross-Region Backup

Automated cross-region backup:

  1. Vào RDS → Automated backups
  2. Enable Cross-Region automated backups
  3. Destination region: Chọn region thứ 3 (ví dụ: eu-west-1)
